# Project DIVA PC Map Editor 行为规格（对齐基准）

本文件是对 **GameMaster「Project DIVA Map Editor」（PC 编辑器，无公开源码）** 的静态逆向结论汇总，
用作 `osu.Game.Rulesets.Diva` 编辑器与格式读写的行为基准。

- 分析方式：**纯静态**。未运行编辑器 exe，未运行客户端，未打开 Realm。
- 事实来源（本地分析产物，不入库）：
  - `F:\MUG DIVA\PC Editor\_decompiled\MapEditor\Project DIVA Map Editor.decompiled.cs`
    （ILSpy 输出，72,843 行；`Form1` 起于 65474 行）
  - `F:\MUG DIVA\PC Editor\_decompiled\NOTES-format.md`（格式/读写器）
  - `F:\MUG DIVA\PC Editor\_decompiled\NOTES-ui.md`（网格/编辑语义）
  - `F:\MUG DIVA\PC Editor\_decompiled\NOTES-game.md`（游戏本体 `ProjectDIVA/src` 交叉验证）
- 引用约定：
  - `[ed:NNNN]` = 上表反编译文件的行号
  - `[game:path:line]` = `e:\BASE CODE\GitHub\ProjectDIVA\src\ProjectDIVA\` 下原生 C++ 源码行列
  - `[ED]` = 仅由编辑器（反编译）确证；`[GAME]` = 仅由游戏本体确证；`[BOTH]` = 两侧一致
- 反编译变量名（`num1/text/num3`…）无语义，一律忽略；结论只依据文件流操作与结构体字节偏移。
- **不确定项集中列在 §11**，未确证处一律标 UNKNOWN，不做推测。

## 0. 结论速览

| 项 | 结论 |
|---|---|
| 编辑器工程文件 | `.divaproject`，**UTF-16 LE + BOM**（写），ANSI（读）——写读编码不自洽 `[ed:69275,69563]` |
| 可发布文件 | `.diva`，**ANSI**，纯文本、CRLF、逐行；游戏只认这一种 `[ed:69275][game:Gui.cpp:1415]` |

## 1. 文件格式

### 1.1 `.divaproject`（工程文件，`build=false`）

入口：`Map_Save` `[ed:69538]` / `另存为` `[ed:71277]`；打开：`OpenFile`，过滤器
`"DIVA Map工程文件|*.divaproject"` `[ed:71258]`。编码 `Encoding.Unicode` `[ed:69275]`。

逐行写入顺序（`g = period*192 + slot` 为**全局帧号**）：

| 行 | 内容 | 来源 |
|---|---|---|
| 1 | `1.0.4.7` | `EditorVer` `[ed:69276]` |
| 2–5 | 歌曲名 / 谱师 / 音乐家 / 风格 | `_mapName,_noterName,_authorName,_musicStyle` `[ed:69277-69280]` |
| 6 | 预览图资源编号（int） | `NoteMap+0` `[ed:69281]` |
| 7 | 难度分类（1..5） | `NoteMap+4` `[ed:69293]` |
| 8 | 难度星级 | `NoteMap+8` `[ed:69294]` |
| 9 | 头 BPM（double） | `NoteMap+24` `[ed:69295]` |
| 10 | 小节数 N | `NoteMap+56848032` `[ed:69296]` |
| 11… | **BPM 段** `<g> <BPM>`，仅 `_IsSetBPM` 为真的帧 | `[ed:69299-69326]` |
| — | `-1` | `[ed:69326]` |
| … | **资源段** `<g> <resourceId>`，仅 `resource != -1` | `[ed:69327-69357]` |
| — | `-1` | `[ed:69357]` |
| … | **BGM 段** `<g> <槽号0..9> <wavId>`，仅 `!= -1` | `[ed:69358-69397]` |
| — | `-1` | `[ed:69397]` |
| … | **音符段** `<g> <n0> <n1> <n2> <n3> <n4> <n5>[ <n6>]`（`n0>=8` 才有 `n6`） | `[ed:69398-69451]` |
| — | `-1` | `[ed:69451]` |
| … | **Key 音段** `<i> <绝对路径>`，`i=0..998`，仅非空 | `[ed:69452-69471]` |
| — | `-1` | `[ed:69472]` |
| … | **资源段** `<i> <绝对路径>`，`i=0..998`，仅非空 | `[ed:69473-69499]` |
| — | `-1` | `[ed:69500]` |
| … | **ChanceTime 行** `<NoteMap+12> <NoteMap+16>`（同一行两个 int） | `[ed:69501-69503]` |
| … | **STOP 段** `<g> <STOP>`，仅 `!= 0`（**只此模式有**） | `[ed:69504-69532]` |
| — | `-1` | `[ed:69533]` |

要点：

- **STOP 不参与工程文件的 g**：工程格式的 `g` 是“不含停机的音乐小节网格”，停机信息单独存 `STOP` 段。
- 6 段位置表都以独立 `-1` 收尾；`build=false` 文件的最后一行恒为 `-1` `[ed:69533]`。
- 首行**读取时不校验**，仅用于版本门 `[ed:69564]`。

### 1.2 `.diva`（发布文件，`build=true`）

入口：菜单 `生成可发布文件`（F9）`[ed:71506]` → `BuildMap` `[ed:71495]`：

```
Projects\<mapName>\<mapName>{levelST[NoteMap+4 - 1]}.diva     // [ed:71501]
levelST = { "_Easy","_Normal","_Hard","_Extra","_FUCK" }        // [ed:56237]
```

与工程文件的**全部差异** `[ed:69273-69535]`：

| 项 | `build=false` | `build=true` |
|---|---|---|
| 编码 | UTF-16 | ANSI `[ed:69275]` |
| 第 6 行 | int（资源下标） | 预览图**文件名**；是图片则 2 次幂化后复制到 `Projects\<mapName>\` `[ed:69286-69291]` |
| 事件位置 `g` | `p*192 + s` | `p*192 + 累计STOP + s`（BPM/资源/BGM/音符**四段各自独立累计**）`[ed:69314,69344,69383,69435]` |
| Key 音/资源路径 | 绝对路径 | 改写成 `WAV\<名>` / `RES\<名>` 并把文件复制进 `Projects\<mapName>\WAV\|RES\` `[ed:69464,69484]` |
| STOP 段 | 写出 | **整段不写**，文件在 ChanceTime 行后结束 `[ed:69504]` |

→ **发布格式 = STOP 已烘焙进位置的时间轴**；游戏只认发布格式，且游戏侧**完全没有 STOP 概念**
`[game:notemap.h:37-51][game:notemap.cpp:99-279]`。

### 1.3 与游戏侧解析的对应

游戏 `NoteMap::SetNew` 用 `fopen("r")` + `fgets/fscanf` 逐 token 读同一份 ANSI 文本 `[game:notemap.cpp:105]`，
行序与 §1.2 完全一致，含 `n6` 仅在 `n0>=8` 出现的同一门控 `[game:notemap.cpp:218-236]`。
游戏**不读** STOP 段、**不读**第 6 行（预览图被丢弃）`[game:notemap.cpp:132-134]`，且
`EditorVer >= "1.0.1.0"` 才读 ChanceTime `[game:notemap.cpp:276]`。

**游戏侧注意点（编辑器产出必须满足）**：

- 事件 `g` 必须 `< N*192`：游戏按 `N*192` 分配帧数组且**无越界检查** `[game:notemap.cpp:141,226]`。
- 至少需要**第 0 帧存在 BPM 事件**：游戏时间基从 `singleTime = 1` tick 起算，只有遇到 `_BPM > 0` 的帧才更新
  `[game:notemap.cpp:173,178-182]`。**编辑器新建工程默认不写任何 BPM 事件**（只写头 BPM=120，
  BPM 段仅 `-1`）`[ed:67351-67375]`；实际谱面靠导入器（BMS/osu!/`.diva`）在第 0 帧写入
  `_IsSetBPM=1, BPM=120` `[ed:70155][ed:70900]`。

## 2. 时间点（Frame）与音符（Note）数据模型

编辑器内存中的时间点记录 = **296 字节**，每 192 帧后追加 16 字节前缀，小节步长
`56848 = 192*296 + 16`；帧数组自 `NoteMap+48` 起 `[ed:69317,69669]`。
帧内字段（相对帧首）：

| 偏移 | 字段 |
|---|---|
| 0 | `Note notes[8]`，每个 **28 字节** |
| 224 | `int BGM[10]`（-1 = 空） |
| 264 | `int resource`（`_resource` 下标，-1 = 无） |
| 272 | `double BPM`（默认 120.0） |
| 280 | `bool _IsSetBPM` |
| 284 | `int _noteNum` |
| 288 | `int STOP` |

音符记录 = **7×int = 28 字节**，写入顺序 `[ed:69105-69128,69435]`，与游戏 `Note` 的字段序一一对应
`[game:notemap.h:25-34]`：

| 索引 | 编辑器写入内容 | 游戏字段 | 含义 |
|---|---|---|---|
| `n0` | `_editState+4`（0..15） | `_type` | **0..7 短音**，**8..15 长条**；`unit = n0 % 8` `[game:notemap.cpp:228]` |
| `n1` | `cellX = (mouseX-17)/12 - 1` | `_x` | 横向格 |
| `n2` | `cellY = (mouseY-45)/12 - 1` | `_y` | 纵向格 |
| `n3` | 精灵/接近点 X | `_tailx` | 游戏只用方向：`dir = unit((n3,n4) - 音符像素)` `[game:GameMana.cpp:434]` |
| `n4` | 精灵/接近点 Y | `_taily` | 同上 |
| `n5` | `listBox1.SelectedIndex`（当前 #WAV） | `_key` | **Key 音 = `_keyWav` 表下标**，不是按键种类 `[game:notemap.h:13]` |
| `n6` | 长条长度（1/192 小节） | `duration` | 仅 `n0>=8` 写；游戏按 `×singleTime` 换算成 tick `[game:GameMana.cpp:766]` |

`unit` 表 `[game:notemap.h:20]`：`0 ○ / 1 □ / 2 × / 3 △ / 4 → / 5 ← / 6 ↓ / 7 ↑`。

**位置唯一性规则（编辑器放置逻辑）** `[ed:68826-69128]`：

- 同一时间点上**每种 unit 至多一条记录**：放置时先查找 `type % 8 == 当前状态 % 8` 的记录，
  命中则**原地覆盖**（含格坐标、精灵坐标、#WAV），未命中才追加并把 `_noteNum++`。
- 长条只在**起始帧**产生一条记录（长度写在 `n6`），中间帧**不写记录** `[ed:69066-69094]`。
- 长条与同 unit 的短音/其它长条区间重叠时弹冲突提示并**可选强制清除**冲突记录 `[ed:68922-69094]`。

### 3.1 编辑器时间轴（左侧 `pictureBox1`）

`maxPeriodPerPage=60`。位图宽恒为 **454** `[ed:67432]`。

（`maxpage = (N-1)/60`，最后一页更短）`[ed:71304]`。

横向列（像素 X → 列号 `posX`）`[ed:67498-67517,68503]`：

| X | posX | 列 |
|---|---|---|
| <19 / 47–50 / 79–82 / 111–114 / 395–398 等 | -1 | 分隔/留白（无动作） |
| 19–46 | 0 | BPM 设置 |
| 51–78 | -2 | STOP 值设置 |

格线/加粗 `[ed:66540,66561,67626,67644]`：格线选项 `4,8,16,32,64,3,6,12,24,48,FREE`
（FREE = 192，逐帧），默认 48；加粗选项 `3,6,12,2,4,8,16,None`，默认 4。
`posGrid = nowpage*格线*60 + e.Y/(384/格线)`，帧号 `= posGrid*192/格线` `[ed:68552,68497]`。

`posC1..posC8`（19/47/83/111/115/399/51/79）**在代码中没有任何读取点**，是死常量，与 8 种音符操作**无关**

### 3.2 PV 区域（右下 `pictureBox3`，480×272）

- 可放置区域：`X∈[17,459] ∧ Y∈[45,223]` `[ed:68819,69116,69173]`。
- 单元格 **12×12 px**：`cellX=(X-17)/12-1`，`cellY=(Y-45)/12-1` `[ed:68827]`
  → 由区域边界得 `cellX∈[-1,35]`、`cellY∈[-1,13]`（负值仍会被写入记录）。
- 图标绘制 **24×24 px = 2×2 格**，`dest = ((cellX+2)*12, cellY*12+51)` `[ed:67938]`
  → 图标中心 = `(12*cellX+36, 12*cellY+63)`，即以存储格为中心向上下左右各外扩 **6 px（半格）**。
- 游戏本体的音符目标点 = `(ORIGIN_X + x*DELTA_X + 12, ORIGIN_Y + y*DELTA_Y + 12) = (37+12x, 64+12y)`
  `[game:GameMana.cpp:120][game:GameIni.h:19-20]` → 与编辑器图标中心**恒差 1 px**（实现细节，非语义差异）。
- 点击命中/删除判定**不做半格扩张**，要求 `(cellX,cellY)` 完全相等 `[ed:69188]`。
  → 使用说明中的“可放置范围上下左右各扩展半格”在反编译代码中**无对应分支**（见 §11）。

### 3.3 放置时精灵（接近方向）默认值

按格坐标推导 `[ed:69110-69128]`：

| 条件 | `n3` | `n4` |
|---|---|---|
| `cellX < 7` | 465 | `cellY*12 + 63`（右侧边缘提示） |
| `cellX > 27` | 15 | `cellY*12 + 63`（左侧边缘提示） |
| 否则 `cellY < 6` | `cellX*12 + 35` | 252（贴底栏） |
| 否则 | `cellX*12 + 35` | 20（贴顶栏） |

即默认接近方向**基本是纵向**（从所在的顶/底栏飞入），与游戏“只取方向、距离固定”的用法一致。

## 4. 时间模型

| 量 | 值 | 出处 |
|---|---|---|
| 帧/小节 | 192 | `[game:notemap.h:16]` |
| 帧/拍 | 48（`192/4`，整数除） | `[game:notemap.h:16,18]` |
| tick/帧 | `Cal_Single(BPM) = 60*SECOND/(BPM*48)` | `[game:notemap.h:131]` |
| ms/帧 | `60000/(BPM*48) = 1250/BPM` | 由上式（`SECOND` = QPC 频率） |
| 小节时长 | `240/BPM` 秒（120 BPM → 2 s） | 同上 |
| 接近提前量 | `note_standing = 192` 帧 = 1 小节 | `[game:GameIni.h:18]` |

帧→时间（`singleTime` 初值 1 tick，遇 `_BPM>0` 的帧才更新）`[game:notemap.cpp:173-186]`：
`t(i) = t(f_k) + (i - f_k) * 1250/B_k`，其中 `B_k` 是 `f_k ≤ i` 的最后一个 BPM 事件；
**BPM 事件帧本身仍使用旧速度**。正值 STOP 使后续事件位置整体后移（见 §1.2）。

音符飞行：方向 `dir = unit((n3,n4) - 目标像素)`，距离 `nowDistance = DISTANCE*120/BPM = 60000/BPM` px
`[game:GameMana.cpp:434,1578][game:GameIni.h:21-22]`；飞行途中走二次 Bézier（控制点偏移 `±0.15*nowDistance`）；
前 12.5% 飞行段按 `NOTE_BLOWUP=1.8 → 1.0` 线性缩放 `[game:GameMana.cpp:405,478][game:GameIni.cpp:5]`。

## 5. 编辑模式与鼠标语义

四种模式（`_editState+0`）`[ed:67662-67786,71729]`：

| id | 模式 | 快捷键 | 数值列（BPM/STOP/#RES/音频） | PV 区左键 |
|---|---|---|---|---|
| 0 | 编辑 | F5 | 已有值可改，空格无动作；右键清除 | 放置音符 |
| 1 | 写入 | F6 | 直接写入/覆盖（悬停即预览青色“即将写入”值） | 放置音符 |
| 2 | 删除 | F7 | 已有值清除，空格无动作；右键清除 | 删除音符 |
| 3 | 改写 | F8 | 同编辑 | **先清空该时间点全部音符**再放置单键；长条分支只清同 unit 冲突 `[ed:68820,68925]` |

音符状态（`_editState+4`，0..15）：0..7 = `○ □ × △ → ← ↓ ↑` 短音，+8 = 同按键的长条；
`ChangeNoteOrBar` 统一加/减 8（Ctrl+X 或工具条 `toolStripButton17`）`[ed:71870]`。

PV 区点击 `[ed:68806-69223]`：

- 左键且模式 ∈ {0,1,3} → 在 `[17,459]×[45,223]` 内放置；**区域外**则把该时间点里 `type%8 == 当前unit`
  的记录 `n3/n4` 直接设为鼠标像素（自由设定接近方向）`[ed:69150-69155]`。
- 长条状态弹输入框 `输入长条长度（单位：1/192小节)`，长度 `<= 0` 报 `输入的数据错误` `[ed:68850-68857]`。
- 冲突提示原文 `[ed:68925,69052]`：
  - `警告：\n此长条与前后的同类型按键有冲突\n是否强制放置？（会清除原来冲突的按键）`
  - `警告：\n此单键与前后的同类型长按键有冲突\n是否强制放置？（会清除原来冲突的按键）`
  - 改写模式**不弹**提示，直接替换。
- 模式 2 或**任意模式右键** → 删除 `(cellX,cellY)` 完全相等的记录（后续记录左移、`_noteNum--`）。

其它：`查看→界面/背景` 控制 PV 底图与面板 `[ed:68141]`；`前/后一小节的音符（红/绿）` 控制预览范围
（后一小节默认不勾）`[ed:67851]`；“上下/左右”扩展见 §11；**无滚轮缩放、无拖拽编辑**
（全文件只有 `MouseClick/MouseMove/MouseLeave`）`[ed:67788,68503]`。

无键盘 `KeyDown` 处理器，快捷键全部来自菜单 `ShortcutKeys` `[ed:66071-66330]`：
`Ctrl+O/S/Shift+S/Q`、`F9` 生成发布文件、`F5–F8` 四模式、`F1–F4` 放置 ○□×△、`Alt+F1–F4` 放置 →←↓↑、
`Ctrl+Delete` 删除当前时间点全部音符、`Ctrl+←/→` 跳至上/下一个有音符的时间点、`Ctrl+↓` 跳至当前时间点。
（`Ctrl+X` 同时绑定“编辑菜单”与“是否为长条放置”；撤销/重做/选择全部/粘贴为 `Enabled=false` 占位。）

## 6. 拷贝 / 剪切 / 删除

- **拷贝/剪切**复用同一对话框（标题分别为 `粘贴`/`剪切`）`[ed:72524,72599]`，6 个输入框：
  `源起小节 + /192`、`源止小节 + /192`、`目标起小节 + /192`；**单位 ÷192 = 帧**
  （`/192 开始 (均以0为起始)`）`[ed:65188-65301]`。
  - 拷贝按**整条 296 字节时间点记录**搬运（含 BPM/STOP/BGM/资源/音符）`[ed:72536-72587]`；
    目标起点早于源时倒序复制；越界部分忽略，提示 `复制完毕，超出部分已忽略`。
  - 剪切 = 拷贝 + 清空源区间（BPM 复位 120、标志清零、`_noteNum=0`、BGM=-1、resource=-1、STOP=0）
    `[ed:72662-72701]`。
- **删除**对话框（标题 `删除NOTE`）`[ed:63644]` 只有起止两对输入 + 静态文字 `到 /192 结束 全部删除`
  （**不是复选框**）`[ed:63714]`；执行时把区间内每个时间点的**音符数清零**，不动 BPM/STOP/音频/资源
  `[ed:72736]`。
- 三者都没有撤销栈（撤销/重做菜单为占位）`[ed:66148]`。

## 7. Chance Time

- 存储：`NoteMap+12`（开始帧）、`NoteMap+16`（结束帧），`-1` = 无；**单位是帧号** `[ed:67349,69502]`。
- 格式：`>=1.0.1.0` 才写/读；写成**同一行的两个 int** `<start> <end>` `[ed:69501,69740]`。
- 游戏消费：`_nowFrame->notePos == _chanceTimeStart` 开始；
  `== _chanceTimeEnd + 1` 结束（**结束帧独占**）`[game:GameMana.cpp:1636,1646]`。
- 期间 COOL/FINE 额外加分 `min(_chanceTimeCombo,50)*100`，非 COOL/FINE 清零 `[game:GameMana.cpp:1033-1042]`。
- 注意：因为游戏按**烘焙后**的位置比对帧号，所以 ChanceTime 的帧号也落在“含 STOP 的时间轴”上。

## 9. 导入器

### 9.1 `.diva` 导入（`ReadDivaFile` `[ed:69788]`）

读的正是 §1.2 发布格式（ANSI）。差异：第 6 行当**文件名**读；Key 音/资源路径前补导入文件所在目录
（`ReadLine().Trim()`）；若资源段的文件名 safename 等于第 6 行则反查 `NoteMap+0`；
`>=1.0.4.2` 时**不读 STOP 段**而是弹
`此diva文件可能包含的STOP信息将丢失` `[ed:69991-69994]`。

### 9.2 BMS 导入（`ReadBMSFile` `[ed:70026]`）

- 以 `*---------------------- MAIN DATA FIELD` 行分界 header/data；CRLF 假设（字符级解析）。
- header：`#TITLE→歌曲名`、`#ARTIST→谱师`、`#GENRE→风格`、`#BPM→头 BPM 且第 0 帧写 BPM 事件`、
  `#PLAYLEVEL→星级`、`#RANK→难度 = 4 - Rank` `[ed:70155-70164]`；
  `#WAVxx` 用 **base-36** 下标且 **1 基**、`#BMPxx` 用 base-36 **0 基**、
  `#BPMxx`/`#STOPxx` 用 **2 位十六进制** `[ed:70172-70214]`。
- data 行：`measure = 3 位十进制`、`channel = 2 位十进制`；第 i 个事件的槽位 = `i*(192/事件数)`；
  通道 `1→BGM`、`3→BPM 直接值`、`4→资源`、`8→#BPMxx`、`9→#STOPxx`，
  `6/7` 忽略；音符通道 `11..19,51..56,58,59` → unit `2,0,7,5,6,1,4,3,10,8,15,13,14,9,12,11`
  （`>=8` 为长音，用 `pending` 回填长度）`[ed:70215-70748]`。
- 结束：`小节数 = maxMeasure + 1` `[ed:70799]`；溢出警告四则原文见 `[ed:70778-70797]`。

### 9.3 osu! 导入（`ReadOSUFile` `[ed:70831]`）

- **时间→帧**：`grid = (int)(ms * 12.0 / 125.0)`，即 1 格 = 125/12 ms、192 格 = 2000 ms `[ed:71199]`。
- **坐标→格**：`n1 = (int)(x*432.0/512.0 + 6.0)/12 - 1`、`n2 = (int)(y*168.0/384.0 + 6.0)/12 - 1`
  （`+6` 即半格四舍五入）`[ed:71173-71174]`。
- 按键轨道按难度旋转（Easy 固定、Normal 0/2 交替、其余 0/1/2/3 循环）`[ed:71096-71127]`。
- 滑条离散成 `slides+1` 个独立音符；`duration = 长度/60*beat`；负 beatLength 只识别 `-200`（×2）与
  `-50`（×0.5）`[ed:71051-71194]`。
- `AudioLeadIn` 被加到所有时间上并在该帧写 `BGM[0] = 1`（音频表第 1 项）`[ed:70962-70990]`。
- Metadata 映射：`Title→歌曲名`、`Artist→音乐家`、`Creator→谱师`、`Source→风格`、
  `Version{Easy,Normal,Hard,Insane,其它}→难度{1,2,3,5,4}` `[ed:70996-71046]`。
- 说明文档提到的「2010.05.09 measure 计算修正」在反编译输出中**无对应注释**（ILSpy 已剥离注释），
  只能列出上述 4 处与位置换算相关的算术，见 §11。

## 10. 与游戏本体的契约（发布谱面必须满足）

1. ANSI 文本、CRLF、发布格式（无 STOP 段）`[game:notemap.cpp:105]`。
2. 事件位置 `g < N*192`（游戏无越界检查）`[game:notemap.cpp:141,226]`。
3. 第 0 帧（或首个 BPM 事件之前）必须有 BPM 事件，否则时间基退化为 1 tick `[game:notemap.cpp:173]`。
4. 单帧音符不超过 **8**（超出会覆盖进 `BGM[]`）`[game:notemap.h:44][game:notemap.cpp:224]`。
5. `n0 ∈ 0..15`、`n1/n2` 为合法格、`n5` 为 `#WAV` 下标（`-1` = 无）`[game:notemap.h:13]`。
6. ChanceTime 行必须存在（`EditorVer >= "1.0.1.0"` 才会被读）`[game:notemap.cpp:276]`。

## 12. Ez 侧对齐状态（格式保真与导出校验）

首轮对齐只处理「`.diva` 读写的字段保真」与「导出前校验」，其余（编辑器交互 / 坐标系）另行分批。

| 项 | 编辑器/游戏事实 | Ez 处理 |
|---|---|---|
| `n5` `#WAV` | 编辑器把当前选中的 `#WAV` 下标写进 `n5`，它对动作判定无意义，但决定 Key 音 | 从源谱面按 `(帧, type)` 取回原值；无源谱面时写 `0`（编辑器对新音符同样为 `0`） |
| `n6` 长条长度 | 游戏按整数读（`fscanf("%d")`），单位帧 | 写整数帧；采样级时长按当前 BPM 量化到最近帧，最小 1 |
| `EditorVer` | 编辑器当前写 `1.0.4.7`（§0）；它是首行的编辑器版本，游戏只拿它做两个门 | 参考编辑器已停更，首行改成本规则集自己的格式版本 `1.1.0.0`（`DIVA_CHART_FORMAT_VERSION`）：lazer 产出的谱面不是 PC 编辑器产出，不复读它的版本号。ChanceTime 行无条件读写（旧谱面缺该行时按容错解析得到「未设置」）。该值必须仍以 `1.` 开头且字典序高于 `1.0.4.7`，理由见下 |
| legacy BPM 取整 | 仅当版本行**不带** `\r` 且 `<= 1.0.4.7` 时命中；编辑器写 CRLF，故永不命中（§11-11） | 解析时不再取整，避免悄悄改动游戏原样播放的 BPM |
| 小节数上限 | 编辑器输入框 1..1000；帧数组按该值分配 | 导出前校验，超过 1000 拒绝并报错 |
| 单帧音符上限 | 帧记录仅 8 个音符槽（`NOTENum`），超出覆盖该帧 `BGM[]`（§10-4） | 导出前校验，超过 8 拒绝并报错（编辑器与游戏本体都不自行钳制） |

首行（`EditorVer`）不是「产出方版本号」，而是三方共用的判别符与门，因此取值受硬约束：

- 三个读入口按 **`"1."` 前缀**识别谱面（`DivaBeatmapDecoder` / `DivaStoryboardDecoder` 的 `AddDecoder`、`DivaTextChartFormat.CanHandle`）；
- 游戏 `notemap.cpp:276` 要求 `EditorVer >= "1.0.1.0"`，否则整行 ChanceTime 不读；
- 游戏 `notemap.cpp:161` 对 `EditorVer <= "1.0.4.7"` 触发 legacy BPM 取整；我们写 `1.1.0.0`，该分支不可能命中（PC 编辑器旧谱面靠 CRLF 残留的 `\r` 同样不命中，见 §11-11）；
- PC 编辑器 `ReadDivaFile` 用同一组门（`1.0.1.0` / `1.0.4.2`）`[ed:69986,69991]`。

故只写名称或以 `0.` 开头都会静默丢 ChanceTime 或触发 BPM 取整，`1.1.0.0` 是同时满足三者、且不再冒用 PC 编辑器版本号的最小取值。改动只有格式布局变化时才 bump（`DivaChartConstants.DIVA_CHART_FORMAT_VERSION`），并有单测把这三条排序约束钉住。

- ChanceTime `ui:L7` → Ez 用 EffectPoint + 事件工具箱表达；单位用 ms 是编辑器惯例，接受差异。

- 格式侧对齐（`n5`/`n6`/首行/legacy BPM/小节数上限/单帧上限）见 §12。

### 13.4 待实测验证（不擅自改规则语义）

- **同按键 tap 落在长条内是否可打**：Ez 的 tap 与 hold 各自独立判定（`DrawableDivaHitObject`），规则层没有互斥；PC 编辑器把它当冲突并提示清除。当前只做 Warning + 手动清理工具，**不**在放置时硬拦截、不删音符。
- **单帧 8 音符上限的提示形式**：PC 与游戏都不钳制（§11-4）；Ez 选「Verify 面板 Warning/Error 提示而不禁止放置」，是否要改为放置即拒绝待实测（真实谱面是否会用到同帧 8 音符的极限写法）。

### 13.5 有意保留的语义差异

- **区间拷贝不搬 BPM / STOP**：PC 的区间对话框搬的是整条时间点记录（含 BPM / STOP / 音频槽 / 资源号）。Ez 的帧 ↔ 毫秒映射由 BPM 表推出（`DivaChartBuilder.FrameToTime`），先搬 BPM 点会让同一操作里已算好的落点漂移，因此只搬随帧记录走的音符与 BGS/RES 事件；要改 BPM 走上游时间轴。若日后要做「连 BPM 一起搬」，需要先在帧空间完成搬运再重新解算毫秒，且要能回滚。
- **区间删除只清音符**：PC 的区间删除同样不动 BPM / STOP / 音频 / 资源列，这里一致。
